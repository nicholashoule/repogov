## Deprecation Notice (Knowledge)

As of 2026-10-17 the Knowledge page states that Knowledge is **deprecated and will be removed in a
future update**. Existing items are being auto-migrated to Skills (Customize -> Plugins -> Knowledge);
trigger becomes the skill description, content becomes the skill body. Knowledge notes API endpoints are
affected. Migration target: Skills (`SKILL.md`). Evidence: https://docs.devin.ai/product-guides/knowledge

## Configuration Model

Devin now supports **file-based Skills**. It scans six repo directories for
`<skill-name>/SKILL.md`: `.agents/skills/` (recommended), `.devin/skills/`, `.github/skills/`,
`.claude/skills/`, `.cognition/skills/`, `.windsurf/skills/`. Frontmatter: `name` (defaults to directory
name), `description`, `allowed-tools`, and Devin-specific `argument-hint` and `triggers` (e.g. `["user"]`
disables automatic activation). The skills page does not mention `AGENTS.md` or rules files. Environment
setup is a YAML blueprint (generated by Devin, editable, version-controllable). Other persistent context
remains web-managed.

### Knowledge (web-managed, DEPRECATED)

Devin's Knowledge system is configured through the Settings & Library page at
`app.devin.ai`. Each Knowledge item has:

- **Trigger description** — a phrase or sentence Devin uses to recall the item
  when it is relevant to the current task.
- **Content** — a handful of sentences with instructions or context.
- **Scope** — can be pinned to no repo, a specific repo, or all repos.

Organization-level and Enterprise-level Knowledge is shared across team members.
Devin automatically suggests new Knowledge items based on session feedback.

### Repository Setup Notes (web-managed)

The Repo Setup wizard (Settings -> Devin's Machine) includes an **Additional
Notes** step where per-repository instructions can be entered. These notes are
stored in Devin's environment snapshot, not in the repository itself.

### Other File-Based Instructions

There is no official documentation (as of the pages fetched) for `AGENTS.md` or
`.devin/playbooks/*.md` being loaded by Devin automatically. Any
`AGENTS.md` present in a cloned repository may be read by Devin as part of
general codebase context, but there is no guaranteed loading mechanism.

## File Extensions

`.md` (`SKILL.md`) in the skill directories above; YAML blueprint for environment setup.

## repogov Support Status

No repogov preset. Skills use the open `SKILL.md` layout, including `.agents/skills/` and
`.claude/skills/`, so repogov skill-directory rules for other agents may already cover them.
Follow-up: consider `.devin/skills/` and `.cognition/skills/` in skill checks.

Consider documenting Devin integration notes in a project `README.md` or
`docs/` section pointing teams to the Devin knowledge configuration.
